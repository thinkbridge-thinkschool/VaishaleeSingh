WHAT THE FIRST THREE LINES COST, AND WHY THEY ARE THE NEW PART

On Day 29 those three lines were three synchronous POSTs to
/api/quotes/{id}/mark-publishable -- a stand-in that set a flag directly,
because the flow behind it did not exist. That endpoint is deleted.

Each of those quotes now goes:

  POST /api/quotes                 -> QuoteSubmitted written to the outbox
    -> Catalog's relay publishes it
      -> moderation-review-requests (filter widened today to admit it)
        -> QuoteSubmittedHandler opens a Review
  GET  /api/reviews/by-subject/{id}?subject=Quote    -- the script WAITS here
  POST /api/reviews/{id}/approve   -> QuoteApproved, because the translator
                                      reads review.Subject (fixed this morning,
                                      before the code that needed it existed)
    -> catalog-quote-decisions (a subscription that did not exist an hour ago)
      -> QuoteApprovedHandler marks it publishable, publishes QuotePublishable
        -> curation-review-decisions (filter also widened today)
          -> QuotePublishableHandler mirrors the flag onto Curation's snapshots
  GET  /api/quotes/{id}            -- the script WAITS for isPublishable

Three broker hops per quote, nine before the collection work starts. The script
waits on state rather than sleeping, so a wrong filter, a missing subscription
or a dead relay surfaces here as a timeout rather than as a pass that breaks
three steps later.

WHAT THIS PROVES THAT THE INTEGRATION TESTS DO NOT

QuotesPlatform.IntegrationTests runs every handler against a real database and
deliberately stops at the handler boundary: no filters, no subscriptions, no
delivery. Every failure that has cost this project real time lives in exactly
that gap -- the Day 29 publisher collision, this morning's subscription filter,
the topology that did not exist. This transcript is the only evidence covering
it, which is why it is a deliverable rather than a screenshot.

WHAT IT STILL DOES NOT COVER

The rejection path and the revision loop are not in this script -- they are
covered by the integration tests instead, against a real database but without
the broker. A scripted reject-and-resubmit against live infrastructure is the
obvious next addition, and it is named here rather than left for someone to
notice its absence.
