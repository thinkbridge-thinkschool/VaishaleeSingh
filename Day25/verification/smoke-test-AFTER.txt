WHY THIS IS THE END-TO-END IDENTITY PROOF, AND NOT JUST AN UPTIME CHECK.

A zero-secrets result achieved by breaking the application is not a pass, so
the proof script's 13/0 needs this beside it. One 200 from /health/ready
establishes both halves of the identity story at once:

  * THE APP BOOTED, which means the Key Vault reference resolved. Jwt:Secret
    is bound through AddOptions<JwtOptions>().ValidateDataAnnotations()
    .ValidateOnStart() with [Required] and [MinLength(32)], so a missing or
    truncated value is a startup failure, not a later 500. A running process
    is therefore evidence that the app's managed identity authenticated to
    kv-7mo4cimyk4vnk and read a real key -- no assertion in the proof script
    could establish that as directly.

  * THE DATABASE CHECK PASSED, which means EF Core opened a connection to
    sql-quotes-7mo4cimyk4vnk over the managed identity. The server is
    azureADOnlyAuthentication, so there is no password path that could have
    produced this result: 3.59ms of Healthy is a token being accepted.

Service Bus was not exercised by the health probe, so it was not claimed here
at first -- the container logs below settle it directly.

is the correct result for an idle topic and is not a failure.

APPLICATION INSIGHTS -- OPEN AT TIME OF WRITING
------------------------------------------------
A token for https://monitor.azure.com/ is acquired successfully, and no 401 or
403 appears in the log. But a successful TOKEN IS NOT PROOF THE INGESTION ROLE
WORKS, and it is worth being exact about why: Entra issues an access token to
any authenticated principal regardless of what that principal is authorised to
do. RBAC is enforced at the ingestion endpoint, one HTTP call later, and a
missing Monitoring Metrics Publisher grant would surface there as a 403 -- not
at token acquisition.

The first queries returned 0 rows, taken within roughly two minutes of the
requests being made, which is inside normal App Insights ingestion latency
(typically 3-5 minutes). Unresolved rather than failed: re-query after five
minutes, and grep the container log for 403 to distinguish the two.

Nothing else in Day 25 depends on the answer. Telemetry export is the only
thing affected, and no claim in the submission rests on it.
