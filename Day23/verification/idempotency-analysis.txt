THE CLAIM THIS FILE MAKES, PRECISELY
------------------------------------

Not "what-if reports no changes". That result is unreachable for any template
that uses reference(), and pretending otherwise would mean either not using
reference() or not looking at the output.

The claim is: every one of those 6 modifies is what-if measurement error, in one
of three named categories, and none of them describes a resource this template
fails to describe correctly. That is a weaker sentence than "no changes" and it
is the one that is true.

The two REAL drifts this check found on its first run were fixed before this
one. They are recorded below, because a check that only ever confirms is not a
check.


WHAT THE FIRST IDEMPOTENCY RUN CAUGHT
--------------------------------------

1. `+ .../subscriptions/search-index/rules/$Default` — a CREATE against
   resources nothing had touched.

   Day 19 declared a '$Default' rule redefined as `1=0`, on the reasoning that
   "adding a rule does NOT replace '$Default'" and a subscription carrying both
   would match everything. That file was never deployed by anything, so the
   reasoning was never tested. It is wrong: Service Bus deletes the default rule
   when the first explicit rule is added. ARM created '$Default', creating
   'content-changes-only' made the service delete it, and every future
   deployment would have repeated that forever.

   Removed. 'content-changes-only' now reads `= Nochange`. The 'audit'
   subscription keeps its '$Default' TrueFilter precisely because it has no
   explicit rule — the same behaviour from the other side, and what makes audit
   receive everything.

2. `~ properties.template.scale.rules` flipping between shapes:

       - http:   metadata.concurrentRequests: "50"
       + custom: metadata.concurrentRequests: "50", type: "http"

   The template declared `custom:` with type 'http'. Container Apps accepts that
   and normalises it into a native `http` rule, so the template described a
   resource the service cannot store. Permanent drift on a correct resource —
   which is how a team learns to ignore what-if output, and ignoring it is how
   the real change hides.

   Changed to `http:` directly. Gone from this run.
